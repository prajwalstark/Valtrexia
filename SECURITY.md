# Security

What protects tenant data in this codebase, where each control lives, how it is tested, and what is still open. Written at the end of Phase 1.

## What is being protected

- **Each MSP's data from every other MSP.** Clients, assets, backup history, incidents and audit entries.
- **Vendor credentials.** API keys that can read an MSP's entire backup estate.
- **The vendors themselves.** The product must never start, stop or change a backup job.

## Controls

| Control                                                                                             | Where                                                                                                                                                                                                              | How it is tested                                                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Tenant isolation in the database                                                                    | Row-level security policy on every tenant table; `packages/db/prisma/migrations/*_tenant_isolation`                                                                                                                | `tenant-isolation.db.test.ts`: read, update, delete, insert and move across tenants, for every table, on real Postgres                                                                             |
| A new table cannot ship without a policy                                                            | Same migration pattern                                                                                                                                                                                             | Catalog test fails if any table with `tenant_id` lacks a policy, or any table is outside the model                                                                                                 |
| One route to tenant data                                                                            | `withTenant` in `packages/db`; the Prisma client is not exported                                                                                                                                                   | Context does not leak between pooled connections, including 40 interleaved transactions                                                                                                            |
| No cross-tenant references                                                                          | Composite `(tenant_id, id)` foreign keys                                                                                                                                                                           | Inserting a child that points at another tenant's parent is rejected                                                                                                                               |
| The app never runs as a privileged database role                                                    | `Db.assertSafeRole()`, called by the web app (`lib/db.ts`) and the worker at start                                                                                                                                 | Rejects the owner role; passes the runtime role                                                                                                                                                    |
| Tenant id comes only from the verified session                                                      | `apps/web/lib/session-core.ts`                                                                                                                                                                                     | `session-core.db.test.ts`; no input exists through which a caller could name a tenant                                                                                                              |
| Multi-factor authentication is mandatory                                                            | `resolveSession`, in the app as well as in Clerk                                                                                                                                                                   | Sessions without a second factor are refused before anything is provisioned                                                                                                                        |
| Every page and server action checks the session                                                     | `requireTenant()` / `requireOwner()`                                                                                                                                                                               | `guards.test.ts` reads the source and fails if a page or action omits the check                                                                                                                    |
| Owners only manage integrations                                                                     | Role check inside each function in `integrations-core.ts`                                                                                                                                                          | Technician attempts are refused before any vendor call                                                                                                                                             |
| Credentials encrypted at rest                                                                       | Envelope encryption, AES-256-GCM, `packages/core/src/crypto`                                                                                                                                                       | Round trip, tampering in every field, wrong key, spliced envelopes                                                                                                                                 |
| A ciphertext is useless on another tenant or integration                                            | Tenant and integration ids bound in as authenticated data, at both layers                                                                                                                                          | Moving a ciphertext to another tenant or record fails to decrypt                                                                                                                                   |
| Credentials never return to the browser                                                             | Queries name their columns; results contain no key material                                                                                                                                                        | Results, audit entries and logs are searched for every key used in the tests                                                                                                                       |
| Raw vendor payloads never reach the browser                                                         | `dashboard-core.ts` selects named columns                                                                                                                                                                          | Output is searched for payload contents                                                                                                                                                            |
| Nothing sensitive in logs                                                                           | `createLogger` redacts by property name and scrubs message text; `Secret` prints as `[redacted]`                                                                                                                   | Credentials passed every way a caller might, including child loggers and errors                                                                                                                    |
| Read-only towards vendors                                                                           | The connector interface has no write method; the HTTP client only issues `GET`                                                                                                                                     | Every request made in the connector tests is asserted to be `GET`                                                                                                                                  |
| Requests cannot be redirected to another host                                                       | HTTP client refuses paths that leave the base URL, and does not follow redirects; the Datto base URL comes from server configuration only                                                                          | Absolute, protocol-relative, root-relative and climbing paths are refused                                                                                                                          |
| Connection tests cannot be used to try keys at speed                                                | Ten per workspace per minute, counted in Redis across web instances; refused if Redis cannot answer                                                                                                                | `integrations-core.db.test.ts`, `rate-limit.test.ts`                                                                                                                                               |
| Webhooks are authenticated                                                                          | Signature verified before the body is read                                                                                                                                                                         | Unsigned and forged requests return 400 and create nothing (checked against the built app)                                                                                                         |
| Outbound requests to tenant-supplied URLs (webhooks, VSPC consoles) cannot reach internal addresses | `packages/core/src/net/outbound.ts`: https only, every resolved address must be public, connection pinned to the checked addresses, no redirects, bounded time and size. Vendor reads use it as a GET-only `fetch` | Private, mapped and alternately-spelled addresses refused; a name resolving to loopback refused without connecting; the connection uses the checked answer                                         |
| Webhook requests are authenticated                                                                  | HMAC-SHA256 signatures per the Standard Webhooks specification; per-channel secret stored encrypted and shown once                                                                                                 | The specification's own worked example reproduced; tampered body, id, timestamp or secret refused; replay outside five minutes refused                                                             |
| Notification destinations never return to the browser                                               | URL and secret are envelope-encrypted; only the host is kept in clear, for display                                                                                                                                 | Listings, audit entries and logs are searched for the URL's token and the secret                                                                                                                   |
| A VSPC console is only read                                                                         | Connector interface has no write methods; the shared HTTP client and the guarded `fetch` both refuse anything but GET; the key should be created read-only in VSPC                                                 | GET-only assertions on the client, the guarded fetch and the stand-in console                                                                                                                      |
| A company owner's password is never fetched                                                         | VSPC requests name their fields with `select`; company records are never stored                                                                                                                                    | The stand-in console carries an owner password; tests check every request selects fields and that no result or log holds it                                                                        |
| A UniView account is only read                                                                      | Data is read through the GET-only HTTP client; the only other request is the OAuth token request, to a fixed address, with no redirects followed; both hosts are fixed in code                                     | Every request in the connector tests is a GET with the bearer token, except the one token POST; a redirect from the token endpoint is refused                                                      |
| UniView access tokens are never kept                                                                | One token per sync, held in memory by the connector; never stored, never logged                                                                                                                                    | Sync and connection-test logs are searched for the token and the client secret                                                                                                                     |
| Audit trail                                                                                         | `audit_logs`; the runtime role has no `UPDATE` or `DELETE` on it                                                                                                                                                   | Updates and deletes are refused by the database                                                                                                                                                    |
| Demo vendor cannot run in production                                                                | `isMockAllowed`                                                                                                                                                                                                    | Refused when `NODE_ENV=production`, whatever the setting                                                                                                                                           |
| Local encryption key cannot run in production                                                       | `createKeyProviderFromEnv`                                                                                                                                                                                         | Refused when `NODE_ENV=production`                                                                                                                                                                 |
| Production encryption keys never leave the key service                                              | `AwsKmsKeyProvider`: data keys are wrapped and unwrapped by AWS KMS; the app holds only wrapped keys. The IAM role needs only `kms:Encrypt` and `kms:Decrypt`                                                      | Stand-in KMS round trips; the stored key id is the key's ARN                                                                                                                                       |
| KMS itself binds each wrapped key to its tenant and record                                          | The envelope's authenticated data is sent as KMS encryption context; Decrypt names the expected key and the answer's key is checked                                                                                | Copies onto another tenant, record or purpose refused; a relabelled answer refused                                                                                                                 |
| An outage of the key service is not mistaken for bad credentials                                    | `KeyServiceUnavailableError`, distinct from `DecryptionError`; syncs and webhooks retry, forms say nothing was saved                                                                                               | Every KMS failure name mapped; sync, delivery, connect and channel tests during an outage                                                                                                          |
| Keys can be rotated without downtime or exposing values                                             | `RotatingKeyProvider` and `pnpm keys:rotate`: only data keys are re-wrapped, after checking each value's tag; conditional writes; resumable; audited                                                               | Tenants under an old key moved; ciphertexts unchanged; dry run, outage, concurrent replacement and unreadable records; logs searched for values                                                    |
| Connections to Postgres and Redis are encrypted in production                                       | `assertProductionTransport`: `sslmode=verify-full` for Postgres, `rediss://` with a password for Redis; checked by the web app, the worker and the rotation command at startup                                     | Every weaker Postgres mode refused, plain and passwordless Redis refused, messages never repeat a URL                                                                                              |
| Old data does not accumulate                                                                        | `apply_retention`: raw payloads emptied after 90 days, results deleted after 13 months, audit entries after 24 months; floors enforced in SQL; the runtime role still cannot delete audit entries itself           | Ages on both sides of each period, in two tenants; batches; floors refused                                                                                                                         |
| A deleted workspace's data is removed, and only after a hold                                        | Marked by an owner or by Clerk deleting the organization; syncing and notifications stop at once; `purge_due_tenants` deletes by cascade after 30 days and records it in `tenant_deletions`                        | Every tenant table emptied for the deleted tenant and untouched for others; hold under a week refused; the app role cannot delete tenants or read the record                                       |
| Injected scripts do not run                                                                         | Strict Content-Security-Policy with a per-request nonce and `strict-dynamic` (`apps/web/lib/csp.ts`, applied in `proxy.ts`); every page rendered per request so it carries the nonce                               | Checked in a browser on a production build: every script on the public pages carries the nonce, no violations; an injected inline handler is blocked and reported; the 3D dashboard loads under it |
| Production images hold no secrets and run with least privilege                                      | `Dockerfile`: base images pinned by digest; unprivileged `node` user; read-only filesystem with `/tmp` writable; `.env` files never enter the build; all configuration from the environment at run time            | `docker/smoke/run.sh` in CI: each image searched for environment and key files; run read-only as `node`                                                                                            |
| Migrations verify the database's certificate                                                        | Prisma's migration engine does not verify under `sslmode=verify-full`; the migrate image refuses any owner URL without `sslmode=require&sslaccept=strict`                                                          | A test of the check; in CI, an unverified URL refused and a verified one applied against TLS-only Postgres                                                                                         |
| Health checks reveal nothing                                                                        | `/api/health` and `/api/ready` sit outside the session middleware and answer `ok`, `ready`, or the name of the part not ready                                                                                      | Readiness tests; in CI, not ready when Redis is unencrypted                                                                                                                                        |
| Baseline response headers                                                                           | `apps/web/next.config.ts`                                                                                                                                                                                          | Checked against the built app: no framing, no MIME sniffing, strict referrer, HSTS                                                                                                                 |
| Errors do not leak internals                                                                        | Vendor and sync errors use messages we wrote; `app/error.tsx` shows no error text                                                                                                                                  | Connector and sync tests assert the stored and shown messages                                                                                                                                      |
| No secrets in the repository                                                                        | `.env` is ignored; `.env.example` holds placeholders                                                                                                                                                               | Tracked files scanned for key patterns at the end of Phase 1                                                                                                                                       |

Continuous integration runs the type check, lint, every test and a production build on each push, and `pnpm audit --prod` on each push and weekly. The workflow has read-only access to the repository and uses no secrets; its actions are pinned to commits, and a test fails if any of that changes. At the time of writing the audit reports no known vulnerabilities.

## Not verified

These were built and tested in isolation, but never exercised against the real thing:

- **Clerk.** Sign-in, MFA setup, organization creation and webhook delivery have not been run against a live Clerk instance. The session and webhook logic is tested with Clerk replaced by fixed inputs.
- **AWS KMS.** The provider has never called AWS. It is tested against a stand-in that follows KMS's documented behaviour for Encrypt and Decrypt (encryption context, named keys, error names). Check on a real key: that the IAM role's two permissions suffice, that CloudTrail shows the context, and how long a call takes from where the app runs.
- **Datto.** The connector has never called Datto. Its response shapes are assumptions, listed in the README.
- **Veeam VSPC and Kaseya UniView.** Both connectors are built from the vendors' published OpenAPI specifications and tested against stand-ins built to them, but have never called a real console or account. What to check is listed in the README.
- **Email delivery.** Messages are rendered, queued and retried, but no provider is connected yet, so none has been delivered.
- **Production infrastructure.** TLS to Postgres and Redis is required by configuration checks; it has not been run against a managed database or cache.
- **The 3D view on a graphics card.** It was only run with software rendering.

## Open items

Not built. Each should be settled before production use.

1. **Rate limiting** covers connection tests only, shared across web instances through Redis. Other actions are behind sign-in, which Clerk rate limits, and the owner role.
2. **Monitoring and alerting** on the application itself: failed syncs across tenants, queue depth, error rates. A stopped worker is now visible inside the app (assets turn unknown and the dashboard says syncs have stopped), but only to someone looking at it. Nothing pages an operator.
3. **Database backups** of this application's own Postgres.
4. **An independent review.** Nobody other than the author has reviewed this code.
5. **Data export.** A workspace can be deleted, but there is no way for a tenant to export its data first.
